# Безопасность

Репозиторий Botping публичный. Секреты и персональные данные инфраструктуры **не должны** попадать в git.

## Что хранить только локально

| Файл / переменная | Назначение |
|-------------------|------------|
| `.env` | Токен админ-бота, chat_id, публичный адрес VPS, SSH для деплоя |
| `data/*.db` | Токены мониторимых ботов, heartbeat-секреты |
| `DEPLOY_SSH_PASSWORD` | Пароль SSH (только в локальном `.env`, не в репозитории) |

Файл `.env` перечислен в `.gitignore`. Не удаляйте его из игнора и не коммитьте копии с реальными значениями.

## Если секрет или токен утёк

1. **Heartbeat-секрет бота или роутера** — в админ-боте: карточка объекта → «Сменить секрет», обновите переменную окружения в коде бота / скрипте MikroTik, перезапустите.
2. **Токен мониторимого бота** — отзовите у [@BotFather](https://t.me/BotFather), выдайте новый, обновите в Botping («Боты» → карточка).
3. **Токен админ-бота** — новый токен у BotFather, замените `ADMIN_BOT_TOKEN` в `.env` на VPS, перезапустите контейнер.
4. **Случайный коммит с секретом** — немедленно ротируйте секрет, удалите из истории git (`git filter-repo` / BFG) и сделайте force-push; считайте старый секрет скомпрометированным.

## Сообщить об уязвимости

Откройте issue в репозитории без публикации реальных токенов, IP и логов с секретами. В описании используйте вымышленные примеры (см. README).
